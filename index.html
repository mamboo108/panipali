📚 DSA Theory Notes

Detailed placement tutorials and conceptual notes for core Data Structures.
01

Arrays

  • Core Concept: Linear collection of elements of the same type stored in contiguous memory locations.
  • Contiguous Access Advantage: Any element can be accessed in constant time O(1) if its index is known.
  • Address Offset Calculation: Calculated using the formula:
    Address(A[i]) = Base + (i * W)
    where Base is the start address and W is the byte size of each element.
  • Dynamic Arrays:
    • Standard arrays have a fixed size. Dynamic variants (e.g., Python list, C++ std::vector, Java ArrayList) resize themselves when full.
    • When capacity is exceeded, a new memory block (typically double the size) is allocated, elements are copied over, and old memory is freed.
    • Resizing takes O(N) time, but since it occurs infrequently, the insertions have an amortized time complexity of O(1).
Operation Best Case Worst / Average Case Why?
Access O(1) O(1) Calculated via address offsets instantly.
Search O(1) O(n) Linear search must scan all elements in the worst case.
Insert (End) O(1) O(1) (Amortized) O(1) when capacity exists; O(N) only during array resizing.
Insert (Middle/Start) O(1) O(n) Requires shifting elements to the right to clear space.
Delete O(1) O(n) Requires shifting elements to the left to fill the gap.
02

Prefix Sum

  • Core Concept: Optimization technique for Range Sum Queries to reduce query time from O(N) to O(1).
  • Precomputation: We build an array of cumulative sums where prefix[i] stores the sum of elements from index 0 to i:
    prefix[0] = arr[0]
    prefix[i] = prefix[i-1] + arr[i]   (for i > 0)
  • Query Execution: To calculate the sum of elements in range [L, R], use:
    Sum(L, R) = prefix[R] − prefix[L-1]   (if L > 0)
    Sum(0, R) = prefix[R]   (if L = 0) 
# Precomputing Prefix Sum in Python
def build_prefix_sum(arr):
    n = len(arr)
    prefix = [0] * n
    prefix[0] = arr[0]
    for i in range(1, n):
        prefix[i] = prefix[i - 1] + arr[i]
    return prefix
03

Sliding Window

  • Core Concept: Optimizes nested loop subsegments (from O(N²) to O(N)) by tracking a contiguous window defined by left and right boundaries.
  • Fixed-size Window:
    • Maintains a constant window width K.
    • When moving the window right, add the new element at right and subtract the element leaving at left.
    • Updates states in O(1).
  • Variable-size Window:
    • Expands by incrementing the right boundary.
    • If a constraint is violated, shrinks from the left boundary until the window is valid again.
# Finding max sum of K consecutive elements (Fixed Window)
def max_sum_subarray(arr, k):
    n = len(arr)
    if n < k: return -1
    
    # Calculate sum of first window
    window_sum = sum(arr[:k])
    max_sum = window_sum
    
    # Slide the window across the array
    for i in range(n - k):
        window_sum = window_sum - arr[i] + arr[i + k]
        max_sum = max(max_sum, window_sum)
    return max_sum
04

Two Pointer Technique

  • Core Concept: Uses two indices to traverse a linear data structure simultaneously to prune search spaces from O(N²) to O(N).
  • Converging Pointers (Opposite Directions):
    • Pointers begin at opposite ends: l = 0 and r = n - 1.
    • They move towards the middle based on conditions (e.g., finding target sums in a sorted array, reversing elements).
  • Fast & Slow Pointers (Same Direction):
    • Pointers move in the same direction at different speeds.
    • Used for middle element extraction or cycle detection (Floyd's Tortoise and Hare).
# Finding if a sorted array has a pair with sum == target
def has_pair_sum(arr, target):
    l, r = 0, len(arr) - 1
    while l < r:
        curr_sum = arr[l] + arr[r]
        if curr_sum == target:
            return True, (l, r)
        elif curr_sum < target:
            l += 1  # Need a larger sum
        else:
            r -= 1  # Need a smaller sum
    return False
05

Singly Linked List

  • Core Concept: Linear, non-contiguous collection of nodes allocated dynamically on the heap.
  • Node Structure: Each node contains:
    • A Data field to hold values.
    • A Next pointer pointing to the memory address of the next node. The last node references NULL.
  • Key Advantages: Dynamic sizing; insertions and deletions do not require shifting elements.
  • Key Disadvantages: Sequential traversal is required from the head node, making index access O(N).
# Singly Linked List Node representation in Python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None  # Pointer to next Node
Operation Best Case Worst Case Why?
Access / Search O(1) O(n) Must traverse sequentially from head.
Insert (Head) O(1) O(1) Simply change pointers: new_node.next = head.
Insert (End) O(1) O(n) Requires traversing to tail unless tail pointer is maintained.
Delete (Head) O(1) O(1) Just move head pointer: head = head.next.
06

Doubly Linked List

  • Core Concept: Bidirectional linear collection of nodes linked forwards and backwards.
  • Node Structure: Holds a Prev pointer, a Data field, and a Next pointer:
    NULL ← [Prev | Data | Next] ↔ [Prev | Data | Next] → NULL
  • Key Advantages:
    • Can traverse in both forward and backward directions.
    • Deletion is O(1) if a direct reference to the target node is given, since predecessor and successor links are immediately available.
  • Key Disadvantages: Higher memory overhead due to storing the extra prev pointer per node, and slightly more complex link-update logic.
07

Circular Linked List

  • Core Concept: Linear list where the final node (tail) links back to the first node (head) instead of referencing NULL.
  • Typical Applications:
    • CPU Scheduling: OS round-robin task allocation cycles.
    • Multiplayer Games: Tracking active turns circularly.
    • Buffers: Circular audio/video streaming buffers.
💡

Stack vs Queue & Dynamics

  • Why are Linked Lists Dynamic?
    • Arrays require contiguous static allocation at compile-time or dynamic resizing copy operations when full.
    • Linked lists allocate nodes on the heap as needed during runtime. Pointers connect these blocks, meaning memory is allocated and freed on the fly without size boundaries.

Stack vs Queue Comparison

Criteria Stack Queue
Workflow Principle LIFO (Last In First Out) FIFO (First In First Out)
Access Ends Single end (Top) for both push and pop Two ends (Enqueue at Rear, Dequeue at Front)
Core Operations Push, Pop, Peek Enqueue, Dequeue, Front/Rear Peek
Primary Use Cases Backtracking, recursion, undo histories, matching brackets Scheduling, task queuing, asynchronous buffers
08

Stack

  • Core Concept: LIFO (Last In First Out) linear structure. Insertions and deletions occur solely at one designated end called the Top.
  • Complexity: Push, Pop, and Peek operate in constant O(1) time.
  • Primary Applications:
    • Function Call Stack: Tracking return addresses and local environments during recursion.
    • Compiler Parsing: Parentheses/bracket matching and infix-to-postfix conversions.
    • Backtracking: History recording for Undo operations or graph traversals (DFS).
09

Queue

  • Core Concept: FIFO (First In First Out) linear structure. Insertions occur at the Rear, while deletions occur at the Front.
  • Complexity: Enqueue and Dequeue operate in constant O(1) time.
  • Primary Applications:
    • Task Buffering: Process queues in CPU schedulers or printing line-buffers.
    • Graph Traversal: Level-by-level search (BFS) queue trackers.
10

Deque (Double Ended Queue)

  • Core Concept: Linear queue permitting insertion and deletion operations at both the Front and Rear ends.
  • Key Operations: insertFront, insertLast, deleteFront, deleteLast in O(1).
  • Key Applications:
    • Sliding Window Maximums: Tracking max elements inside dynamic ranges in O(N) time.
    • Work-Stealing: Allocating threads efficiently in execution environments.
11

Binary Tree

  • Core Concept: Non-linear hierarchical structure where each node has **at most 2 children** (Left child and Right child).
  • Key Classifications:
    • Full Binary Tree: Every node has either 0 or 2 children.
    • Complete Binary Tree: All levels are filled, except possibly the last level which is populated from left to right.
    • Perfect Binary Tree: All internal nodes have 2 children, and all leaves reside at the same depth.
    • Balanced Binary Tree: The height difference between the left and right subtrees of any node is at most 1.
12

BST (Binary Search Tree)

  • Core Concept: Ordered binary tree enforcing a strict lookup rule:
    Left Subtree Values < Root Value < Right Subtree Values
  • Time Complexity:
    • Average Case: Search, insertion, and deletion operate in O(log N) time.
    • Worst Case (Skewed Tree): If elements are inserted in sorted order, the tree degenerates into a linear chain, degrading operations to O(N).
13

Tree Traversals

  • Core Concept: Strategies to visit every node in a tree systematically.
  • Depth-First (DFS) Traversals:
    • Inorder (Left, Root, Right): Visits left subtree, root, then right subtree. Crucial Property: Inorder traversal of a BST yields elements in sorted ascending order.
    • Preorder (Root, Left, Right): Visits root first, then subtrees. Used to clone trees or parse equations.
    • Postorder (Left, Right, Root): Visits subtrees first, then root. Used for bottom-up node deletions.
  • Breadth-First (BFS / Level Order) Traversal: Visits nodes level by level starting from the root using a queue.
# Recursive DFS Inorder Traversal in Python
def inorder(root):
    if root:
        inorder(root.left)
        print(root.data, end=" ")
        inorder(root.right)
14

Heap

  • Core Concept: Array-represented complete binary tree maintaining the heap property.
  • Index Mapping Formula:
    Left Child of Node at index i = 2i + 1
    Right Child of Node at index i = 2i + 2
    Parent of Node at index i = (i - 1) // 2
  • Properties:
    • Max Heap: Parent node is greater than or equal to its children. Root is the maximum element.
    • Min Heap: Parent node is less than or equal to its children. Root is the minimum element.
  • Key Complexities:
    • Heapify: Corrects heap violations in O(log N) time.
    • Build Heap: Builds a heap from an array in O(N) time.
15

Priority Queue

  • Core Concept: Queue where elements are removed based on priority weight rather than insertion sequence. Typically implemented using a binary heap.

Heap vs BST Comparison

Operation / Feature Binary Heap (Min/Max Heap) Binary Search Tree (BST)
Search Time O(n) (No ordering between siblings) O(log n) average (Ordered left < root < right)
Find Min or Max O(1) (Located at the root) O(log n) (Must traverse to leftmost or rightmost leaf)
Build Time O(n) O(n log n)
Array Representation Yes, very natural since it is complete. No, sparse pointer nodes are needed.

DSA Technical Viva Q&A

Q1: Explain locality of reference in Arrays vs Linked Lists.

  • Spatial Locality: Arrays store elements in contiguous blocks of memory, which allows CPUs to cache adjacent elements during index lookups, generating high cache hit rates.
  • Pointer Overhead: Linked list nodes are scattered across the heap. Accessing the next element requires dereferencing pointers, causing frequent cache misses and slower traversals.

Q2: What is call stack overflow in recursion?

  • Stack Allocation: Each recursive call pushes a stack frame (storing arguments, variables, and return targets) onto the execution stack.
  • Overflow Event: If recursion lacks a base case, or runs too deep, frames accumulate continuously without popping. Once stack size limits are exceeded, a Stack Overflow occurs.

Q3: Why are self-balancing trees (AVL, Red-Black) preferred over standard BSTs in production?

  • Skewing Risk: If items are inserted into a BST in sorted order, the tree becomes skewed (like a linked list), slowing lookups from O(log N) to O(N).
  • Height Bounding: Self-balancing trees execute node rotations during modifications to enforce height bounds, securing O(log N) performance.

Q4: What is amortized time complexity? Explain with Dynamic Array resizing.

  • Average Costing: Amortized complexity evaluates the average time taken per operation over a worst-case sequence.
  • Array Resizing: Appending to a dynamic array takes O(1) time. When capacity is exceeded, it copies all N elements to a new double-sized block (taking O(N)). Because resizing occurs only at size powers of 2, the average cost over N appends resolves to O(1).

Q5: Explain Floyd's Cycle-Finding Algorithm (Tortoise and Hare) for Linked Lists.

  • Pointers Setup: Initialize two pointers (Slow moving 1 node, Fast moving 2 nodes) at the head.
  • Meeting Guarantee: If a loop exists, the fast pointer enters it first. Because the fast pointer closes the gap by 1 node per step, it is guaranteed to meet the slow pointer in O(N) time with O(1) space.

Q6: How does Stack memory differ from Heap memory allocation?

  • Stack Memory: Managed automatically by the CPU, allocated in LIFO order, holds local variables, is extremely fast, and has limited size.
  • Heap Memory: Managed dynamically by runtime controllers/developers, holds global structures, is slower to reference, and has much larger storage capacity.

Analysis and Design of Algorithms. Complexity classes, graph searches, sorting, and design paradigms.
16

Time Complexity

  • Core Concept: Measure of the rate at which execution time grows relative to input size N.
  • Primitive Count: Does not count execution seconds, but rather evaluates the scale of basic machine instructions.
  • Asymptotic Scope: Analyzes behavior as input approaches infinity (N → ∞), discarding constant coefficients and keeping highest-order terms.
17

Space Complexity

  • Core Concept: Total memory consumed by an algorithm relative to input size N.
  • Allocations: Divided into:
    • Input Space: Memory to store input values.
    • Auxiliary Space: Extra temporary memory allocated during processing (e.g., recursions stack, helper tables). Placement interviewers prioritize Auxiliary Space.
18

Big O Notation & Growth Rates

  • Core Concept: Represents the worst-case upper bound of runtime growth.

Common Complexity Classes

Class Name Typical Code Pattern
O(1) Constant Arithmetic operations, array indexing.
O(log N) Logarithmic Binary search (dividing size in half).
O(N) Linear Single loop traversing elements 0 to N.
O(N log N) Linearithmic Divide-and-conquer sorting (Merge, Quick Sort).
O(N²) Quadratic Nested loops (checking pairs).
O(2^N) Exponential Naïve recursion loops, generating subsets.

Comparing Growth Rates

  • Logarithmic (O(log N)): Resolves in ~10 steps for 1,000 items (nanoseconds).
  • Linear (O(N)): Resolves in 1,000 steps (microseconds).
  • Linearithmic (O(N log N)): Resolves in ~10,000 steps (microseconds).
  • Quadratic (O(N²)): Resolves in 1,000,000 steps (milliseconds).
  • Exponential (O(2^N)): Resolves in 2^1000 steps (taking millions of years).
🔑

Why Hashing Improves Complexity

  • Searching Optimization: Unsorted arrays take O(N) search time, and sorted arrays take O(log N). Hashing uses hash mappings to secure O(1) average search.
  • Interview Patterns:
    • Two Sum: Store visited items (seen[val] = idx) to lookup target complements in O(1).
    • Duplicate Searches: Track visited items in a Hash Set to flag matches instantly.
    • Frequency Maps: Track character counts to compare structures in linear time (e.g., Anagrams).
19

BFS (Breadth First Search)

  • Core Concept: Graph traversal visiting neighbor nodes level-by-level starting from the source vertex.
  • Mechanics: Utilizes a **Queue** tracker and a **Visited** array to prevent cycling back.
  • Complexity: O(V + E) (Vertices + Edges).
  • Placement Applications: Finding the shortest path in unweighted graphs and tracking social connection degrees.
20

DFS (Depth First Search)

  • Core Concept: Graph traversal going deep into a branch before backtracking.
  • Mechanics: Utilizes a **Stack** (explicitly or via recursion) and a **Visited** tracking structure.
  • Complexity: O(V + E).
  • Placement Applications: Graph cycle detection, topological sorting, and solving path grids (mazes).

BFS vs DFS Comparison

Feature BFS DFS
Underlying Structure Queue Stack / Recursion
Traversal Strategy Level-by-level (wide) Branch-by-branch (deep)
Memory Demand O(Width of Graph) O(Height of Graph)
Shortest Path Guaranteed for unweighted graphs. Not guaranteed (visits path-by-path).
21

Dijkstra's Algorithm

  • Core Concept: Greedy algorithm finding the shortest path from a single source node to all other vertices.
  • Constraints: Edge weights must be non-negative (Weights ≥ 0).
  • Complexity: O((V + E) log V) when optimized with a Min-Heap/Priority Queue.
  • Dijkstra Fail Case on Negative Edges:
    • Assumes once a node distance is finalized, it cannot improve.
    • Negative edges can break this assumption by introducing a longer path with a negative sum, which Dijkstra will skip since the node was already locked.
    • Alternative: Use **Bellman-Ford** (handles negative weights, detects cycles).
22

Sorting Algorithms

  • Bubble Sort (O(N²)): Swaps adjacent unsorted elements.
  • Selection Sort (O(N²)): Selects the smallest element in each pass to place at the start. Unstable.
  • Insertion Sort (O(N²)): Shifts elements sequentially to build a sorted subarray. Runs in O(N) when already sorted.
  • Merge Sort (O(N log N)): Divide-and-conquer. Recursively splits, sorts, and merges. Stable but requires O(N) auxiliary space.
  • Quick Sort (O(N log N) Avg): Partitions array relative to a pivot in-place. Worst-case is O(N²), unstable. Faster in practice due to cache efficiency.

Merge Sort vs Quick Sort

Criteria Merge Sort Quick Sort
Time Complexity Guaranteed O(N log N) in all cases. O(N log N) average, O(N²) worst case.
Space Complexity O(N) auxiliary space (not in-place). O(log N) stack space (in-place).
Stability Stable (preserves relative order). Unstable.
Cache Performance Average cache performance. Excellent cache performance (faster in practice).
23

Greedy Method

  • Core Concept: Builds solutions by selecting the locally optimal choice at each step, hoping it resolves to a global optimum.
  • Applications: Fractional Knapsack, Dijkstra's algorithm, Prim's/Kruskal's MST, Huffman coding.
  • Greedy Fail Case: Coin Change problems with coin configurations like {1, 3, 4} seeking change of 6 (Greedy yields 3 coins, Optimal is 2).
24

Dynamic Programming (DP)

  • Core Concept: Solves complex problems by caching optimal subproblems. Requires:
    • Overlapping Subproblems: Subproblems are evaluated repeatedly.
    • Optimal Substructure: Global optimal solution incorporates optimal subproblems.
  • Paradigms:
    • Memoization (Top-Down): Recursive caching of states during evaluations.
    • Tabulation (Bottom-Up): Iterative sequence filling a DP table starting from base conditions.

Greedy vs Dynamic Programming

Feature Greedy Paradigm Dynamic Programming (DP)
Choice Evaluation Makes local choice without evaluating subproblems. Evaluates all subproblems to make global choice.
Complexity Faster and uses less memory. Slower and requires a DP state table.
Correctness Not guaranteed to be optimal for all problems. Guaranteed to find optimal solution if DP properties hold.

AAD Technical Viva Q&A

Q1: Stable vs Unstable sorting algorithms - why does it matter?

  • Stability: Preserves the original relative order of items with equivalent sorting keys.
  • Use Case: Vital when sorting database objects sequentially over multiple columns (e.g., sorting by name, then sorting by age group).

Q2: Adjacency Matrix vs Adjacency List for Graphs - when to use which?

  • Adjacency Matrix: Takes O(V²) space. Edge lookups run in O(1). Optimal for dense graphs.
  • Adjacency List: Takes O(V + E) space. Edge lookups run in O(degree). Optimal for sparse graphs.

Q3: Explain the difference between Divide & Conquer and Dynamic Programming.

  • Divide & Conquer: Solves independent subproblems sequentially (e.g., Merge Sort splits left and right independently).
  • Dynamic Programming: Caches optimal results for overlapping subproblems (e.g., Knapsack subproblem results are shared).

Q4: What is Auxiliary Space and how does it differ from Space Complexity?

  • Space Complexity: Sum memory needed including input data storage buffers.
  • Auxiliary Space: Temporary run-time memory structures allocated by processing (e.g., variables, helper lists, recursion stack).

Q5: What are collision resolution techniques in Hashing?

  • Chaining: Buckets link to pointer chains of duplicate hashes.
  • Open Addressing: Resolves matches inside the table using Linear, Quadratic, or Double Hashing probes.

Q6: Why does Dijkstra's algorithm fail for negative edge weights? Give a numerical example.

  • Locked Vertex: Dijkstra locks a node's distance once evaluated.
  • Numerical Example: Directed edges: A -> B (5), A -> C (2), and B -> C (-10). Dijkstra visits and locks C at distance 2 first. It then visits B at distance 5. The route A -> B -> C weighs -5, but since C is already locked, Dijkstra fails to update it.

Percentage

Core Conversions
x% = x / 100
e.g. 20% = 20/100 = 1/5
a/b as % = (a/b) × 100
e.g. 1/4 = 25%
Percentage Change in Consumption
Price increases by R% → reduce consumption by:
[R / (100 + R)] × 100 %
(to keep expenditure unchanged)
Price decreases by R% → increase consumption by:
[R / (100 − R)] × 100 %
(to keep expenditure unchanged)
Population Growth
Population after n years = P × (1 + R/100)ⁿ
Population n years ago = P / (1 + R/100)ⁿ
Depreciation
Value after n years = P × (1 − R/100)ⁿ
Value n years ago = P / (1 − R/100)ⁿ
Comparative Percentage
A is R% more than B → B is less than A by:
[R / (100 + R)] × 100 %
A is R% less than B → B is more than A by:
[R / (100 − R)] × 100 %
02

Profit & Loss

Basic Relations
  • Gain = SP − CP  (when SP > CP)
  • Loss = CP − SP  (when SP < CP)
  • Gain / Loss is always calculated on CP
Percentage Formulas
Gain % = (Gain / CP) × 100
Loss % = (Loss / CP) × 100
Selling Price
SP = [(100 + Gain%) / 100] × CP
e.g. sold at 35% gain → SP = 135% of CP
SP = [(100 − Loss%) / 100] × CP
e.g. sold at 35% loss → SP = 65% of CP
Cost Price
CP = [100 / (100 + Gain%)] × SP
CP = [100 / (100 − Loss%)] × SP
Special Cases
Two items sold each at ±x% (one gain, one loss):
Net Loss % = (x/10)² %
Always a loss when same % used for gain & loss
False weight trick:
Gain % = [Error / (True value − Error)] × 100

Time & Work

Core Principle
A finishes work in n days → A's 1 day work = 1/n
A's 1 day work = 1/n → A finishes in n days
Combined Work
A (n days) + B (m days) together:
Together finish in = nm/(n+m) days
Efficiency Ratio
A is k times as efficient as B:
Work ratio A:B = k:1
Time ratio A:B = 1:k
04

Ratio & Proportion

Basics
  • Ratio a:b = a/b  (a = antecedent, b = consequent)
  • Multiplying/dividing both terms by same nonzero number does not change the ratio
Proportion
  • a:b = c:d → a:b::c:d (a, d = extremes; b, c = means)
  • Product of means = Product of extremes: b×c = a×d
  • Fourth proportional to a,b,c → d = bc/a
  • Third proportional to a,b → c = b²/a
  • Mean proportional between a and b → √(ab)
Derived Ratios
Compounded ratio of (a:b), (c:d), (e:f) = ace : bdf
Duplicate ratio of a:b = a² : b²
Sub-duplicate = √a : √b
Triplicate = a³ : b³
Sub-triplicate = a^(1/3) : b^(1/3)
Componendo & Dividendo:
If a/b = c/d → (a+b)/(a−b) = (c+d)/(c−d)
Variation
Direct: x ∝ y → x = ky
Inverse: x ∝ 1/y → xy = k

Average

Core Formula
Average = Sum of observations / Number of observations
Average Speed
Equal distances at speeds x and y kmph:
Average speed = 2xy / (x + y) kmph
This is the Harmonic Mean of x and y

Numbers / HCF & LCM

Algebraic Identities
  • (a+b)(a−b) = a² − b²
  • (a+b)² = a² + 2ab + b²
  • (a−b)² = a² − 2ab + b²
  • (a+b+c)² = a²+b²+c²+2(ab+bc+ca)
  • a³+b³ = (a+b)(a²−ab+b²)
  • a³−b³ = (a−b)(a²+ab+b²)
  • a³+b³+c³−3abc = (a+b+c)(a²+b²+c²−ab−bc−ca)
  • If a+b+c = 0 → a³+b³+c³ = 3abc
HCF & LCM Key Rules
HCF × LCM = Product of two numbers
Valid for exactly two numbers
HCF of fractions = HCF of numerators / LCM of denominators
LCM of fractions = LCM of numerators / HCF of denominators
BODMAS Order
Brackets → Of → Division → Multiplication → Addition → Subtraction
Bracket order: ( ) → { } → | |
Modulus
|a| = a if a > 0 ; −a if a < 0
e.g. |−5| = 5, |5| = 5

Permutation & Combination

Factorial
n! = n × (n−1) × (n−2) × … × 2 × 1
0! = 1  |  4! = 24  |  5! = 120
Permutations (Ordered)
ⁿPᵣ = n! / (n−r)!
= n(n−1)(n−2)…(n−r+1)
e.g. ⁶P₂ = 6×5 = 30
All n taken at a time: ⁿPₙ = n!
Repeated elements (p₁ alike, p₂ alike …):
Arrangements = n! / (p₁! × p₂! × … × pᵣ!)
where p₁+p₂+…+pᵣ = n
Combinations (Unordered)
ⁿCᵣ = n! / [r! × (n−r)!]
e.g. ¹¹C₄ = (11×10×9×8)/(4×3×2×1) = 330
ⁿC₀ = ⁿCₙ = 1
ⁿCᵣ = ⁿC₍ₙ₋ᵣ₎
e.g. ¹⁶C₁₃ = ¹⁶C₃ = 560

Probability

Core Formula
P(E) = n(E) / n(S)
n(E) = favourable outcomes, n(S) = total outcomes
Key Results
  • P(S) = 1  (certain event)
  • 0 ≤ P(E) ≤ 1
  • P(∅) = 0  (impossible event)
  • P(A∪B) = P(A) + P(B) − P(A∩B)
  • P(A') = 1 − P(A)  (complement)
Standard Sample Spaces
  • 1 coin toss: S = {H, T}  → n(S) = 2
  • 2 coins: S = {HH, HT, TH, TT}  → n(S) = 4
  • 1 die: S = {1,2,3,4,5,6}  → n(S) = 6
  • Deck of cards: n(S) = 52  (13 per suit × 4 suits)
  • Face cards per suit: King, Queen, Jack → 3; total = 12
  • Red cards = Hearts + Diamonds = 26; Black = Spades + Clubs = 26

Simple & Compound Interest

Simple Interest
SI = (P × R × T) / 100
P = (100 × SI) / (R × T)
R = (100 × SI) / (P × T)
T = (100 × SI) / (P × R)
P = Principal, R = Rate % p.a., T = Time in years
Compound Interest — Amount Formulas
Compounded Annually:
A = P × (1 + R/100)ⁿ
Compounded Half-yearly:
A = P × (1 + R/200)²ⁿ
Rate halved, periods doubled
Compounded Quarterly:
A = P × (1 + R/400)⁴ⁿ
Rate quartered, periods quadrupled
Annually, time = 3½ years:
A = P × (1 + R/100)³ × (1 + R/200)
Whole years use full rate; fraction year uses proportional rate simply
Different rates R₁, R₂, R₃ for years 1, 2, 3:
A = P × (1+R₁/100)(1+R₂/100)(1+R₃/100)
CI & Present Worth
CI = A − P
Present Worth of amount x due n years hence:
PW = x / (1 + R/100)ⁿ

Speed, Time & Distance

Core Relations
Speed = Distance / Time
Time = Distance / Speed
Distance = Speed × Time
Unit Conversion
km/hr → m/s : × 5/18
m/s → km/hr : × 18/5
Speed Ratio & Time Ratio
Speed ratio A:B = a:b
→ Time ratio A:B = b:a
(Same distance; time inversely proportional to speed)
Average Speed

Avg speed = 2xy / (x + y) km/hr
Harmonic mean of the two speeds

Problems on Trains

Conversion (same as speed)
km/hr → m/s : × 5/18  |  m/s → km/hr : × 18/5
Time to Cross
  • Train (length l) crosses a pole / standing person → covers l metres
  • Train (length l) crosses stationary object (length b) → covers (l + b) metres
Relative Speed
Same direction (u > v): Relative speed = u − v
Opposite directions: Relative speed = u + v
Crossing Each Other
Trains of length a & b, opposite directions:
Time = (a + b) / (u + v) sec
Same direction:
Time = (a + b) / (u − v) sec
Speed Ratio (Meeting Problem)
Two trains start from A & B, after crossing take a sec and b sec to reach opposite ends:
Speed A : Speed B = √b : √a
Note: ratio is √b : √a, not b : a

Boats & Streams

  • Upstream: against the stream (boat − current)
Speed Formulas

Downstream speed = u + v

Stocks & Shares

Key Definitions
  • Face Value (FV): printed value on share certificate — always fixed
  • Market Value (MV): current traded price — changes daily
  • Dividend: annual profit paid on face value
  • At premium: MV > FV  |  At par: MV = FV  |  At discount: MV < FV
  • Brokerage: added when buying; subtracted when selling
Market Value Examples
Rs.100 stock at premium of 16 → MV = Rs.116
Rs.100 stock at discount of 7 → MV = Rs.93
Number of Shares & Yield
No. of shares = Total Investment / MV per share
               = Total Income / Dividend per share
Rate of return % =
(Annual dividend / MV) × 100
e.g. 9% stock at 120 → return = (9/120)×100 = 7.5%

Banker's & True Discount

True Discount Concepts
  • Present Worth (PW): amount paid now to clear a future debt
  • True Discount (TD) = Sum due − PW = SI on PW
  • Amount = PW + TD
True Discount Formulas
PW = (100 × Amount) / (100 + R×T)
TD = (Amount × R × T) / (100 + R×T)
TD = (PW × R × T) / 100
Sum due (when SI and TD known):
Sum = (SI × TD) / (SI − TD)
PW with compound interest:
PW = Amount / (1 + R/100)ᵀ
Banker's Discount Formulas
BD = SI on Face Value for unexpired time
BD = (Amount × R × T) / 100
BG = BD − TD = SI on TD = TD² / PW
TD = √(PW × BG)
Amount = (BD × TD) / (BD − TD)
TD = (BG × 100) / (R × T)

Logarithms, Surds & Indices

Logarithm Definition
aᵐ = x  ⟺  m = logₐ x
e.g. 10³ = 1000 ↔ log₁₀ 1000 = 3
e.g. 3⁴ = 81 ↔ log₃ 81 = 4
Log Properties
logₐ(xy) = logₐx + logₐy
logₐ(x/y) = logₐx − logₐy
logₐ(xⁿ) = n·logₐx
logₓ x = 1
logₐ 1 = 0
logₐ x = 1 / logₓ a
logₐ x = log x / log a (change of base)
Laws of Indices
aᵐ × aⁿ = aᵐ⁺ⁿ
aᵐ / aⁿ = aᵐ⁻ⁿ
(aᵐ)ⁿ = aᵐⁿ
(ab)ⁿ = aⁿbⁿ
(a/b)ⁿ = aⁿ/bⁿ
a⁰ = 1
Laws of Surds
ⁿ√a = a^(1/n)
√(ab) = √a × √b
√(a/b) = √a / √b
(√a)ⁿ = a^(n/2)

Chain Rule

Direct & Indirect Relations
  • Direct Proportion: if one quantity increases, the other increases proportionally. Set up as a direct ratio. (e.g. more articles → more cost)
  • Indirect Proportion: if one increases, the other decreases. Invert the ratio. (e.g. more speed → less time)
  • For multi-variable problems, compare each item with the unknown and multiply all ratios together.

Calendar

Leap Year Rules
  • Divisible by 4 but not a century → Leap year
  • Century year divisible by 400 → Leap year (e.g. 400, 800, 1200, 1600, 2000)
  • Century year NOT divisible by 400 → NOT a leap year (e.g. 100, 200, 300, 1800, 2100)
  • Leap year = 366 days; Ordinary year = 365 days
Odd Days
1 ordinary year = 52 weeks + 1 odd day
1 leap year = 52 weeks + 2 odd days
100 years → 5 odd days
200 years → 3 odd days
300 years → 1 odd day
400 years → 0 odd days
800, 1200, 1600, 2000 … → 0 odd days each
Odd Days → Day of Week
0 = Sun | 1 = Mon | 2 = Tue | 3 = Wed | 4 = Thu | 5 = Fri | 6 = Sat

Clocks

Speed of Hands
Minute hand: 360° in 60 min = 6°/min
Hour hand: 360° in 12 hrs = 0.5°/min
Relative speed: 5.5°/min
Minute hand gains 5.5° over hour hand per minute
Key Results
  • In 60 minutes, minute hand gains 55 minute-spaces on hour hand
  • Both hands coincide once every hour
  • Hands at right angles (90°): 15 minute-spaces apart — happens twice per hour
  • Hands opposite (180°): 30 minute-spaces apart — happens once per hour
  • Clock fast: shows time ahead; Clock slow: shows time behind
Angle Formula
Angle between hands at H hrs M mins:
θ = |30H − 5.5M|°
If θ > 180°, subtract from 360°

Volume & Surface Area

Cuboid (l × b × h) & Cube (edge a)
Cuboid Volume = l × b × h  |  SA = 2(lb + bh + lh)  |  Diagonal = √(l² + b² + h²)
Cube Volume = a³  |  SA = 6a²  |  Diagonal = a√3
Cylinder (r, h) & Cone (r, h)
Cylinder Volume = πr²h  |  Curved SA = 2πrh  |  Total SA = 2πr(h + r)
Cone Slant height l = √(h² + r²)  |  Volume = (1/3)πr²h  |  Curved SA = πrl  |  Total SA = πr(l + r)
Sphere (r) & Hemisphere (r)
Sphere Volume = (4/3)πr³  |  SA = 4πr²
Hemisphere Volume = (2/3)πr³  |  Curved SA = 2πr²  |  Total SA = 3πr²
1 litre = 1000 cm³
