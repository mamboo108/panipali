📚 DSA Theory Notes

Detailed placement tutorials and conceptual notes for core Data Structures.
01

Arrays

An array is a linear data structure containing elements of the same type stored in contiguous memory locations. Since memory is contiguous, any element can be accessed in constant time if its index is known.

Memory Address Calculation: Given the base address of the array Base, the size of each element W, and an index i, the address of the element at index i is calculated as:

Address(A[i]) = Base + (i × W)

Dynamic Arrays: Standard arrays are static (fixed size). Dynamic arrays (like Python list, C++ std::vector, Java ArrayList) automatically resize themselves when full. When the array is full, a new memory block of double the size is allocated, elements are copied, and the old memory is freed. The copy operation takes O(N), but since this resizing occurs infrequently, the insertion at the end has an amortized time complexity of O(1).

Operation Best Case Worst / Average Case Why?
Access O(1) O(1) Calculated via address offsets instantly.
Search O(1) O(n) Linear search must scan all elements in the worst case.
Insert (End) O(1) O(1) (Amortized) O(1) when capacity exists; O(N) only during array resizing.
Insert (Middle/Start) O(1) O(n) Requires shifting elements to the right to clear space.
Delete O(1) O(n) Requires shifting elements to the left to fill the gap.
02

Prefix Sum

Used to optimize range sum queries. Instead of calculating the sum of elements from index L to R by iterating (O(N) per query), we precompute a prefix sum array in O(N) time. This allows us to answer any range sum query in O(1) time.

Definition: prefix[i] stores the sum of elements from index 0 to i.

prefix[0] = arr[0]
prefix[i] = prefix[i-1] + arr[i]   (for i > 0)

Query Formula: To get the sum of subarray arr[L...R]:

Sum(L, R) = prefix[R] − prefix[L-1]   (If L > 0)
Sum(0, R) = prefix[R]   (If L = 0) 
# Precomputing Prefix Sum in Python
def build_prefix_sum(arr):
    n = len(arr)
    prefix = [0] * n
    prefix[0] = arr[0]
    for i in range(1, n):
        prefix[i] = prefix[i - 1] + arr[i]
    return prefix
03

Sliding Window

The sliding window technique converts nested loops (O(N²)) into a single loop (O(N)) for problems involving contiguous subarrays or subsegments. We define two boundaries (left and right) representing a window that "slides" over the array.

Fixed-size Window: Maintain a window of size K. When expanding the window to the right by adding arr[right], we slide it by removing the element at the left arr[left]. This keeps the window size constant while updating the status (e.g., sum, characters count) in O(1).

Variable-size Window: Expand the window by incrementing the right boundary. If a constraint is violated, shrink the window from the left boundary until the constraint is satisfied again.

# Finding max sum of K consecutive elements (Fixed Window)
def max_sum_subarray(arr, k):
    n = len(arr)
    if n < k: return -1
    
    # Calculate sum of first window
    window_sum = sum(arr[:k])
    max_sum = window_sum
    
    # Slide the window across the array
    for i in range(n - k):
        window_sum = window_sum - arr[i] + arr[i + k]
        max_sum = max(max_sum, window_sum)
    return max_sum
04

Two Pointer Technique

The Two Pointer technique uses two indices (pointers) to traverse a data structure (typically a sorted array or linked list) to optimize searching space. Instead of checking every pair (O(N²)), we move pointers based on conditions to solve in O(N) time.

Variants:

  • Opposite Direction (Converging): One pointer starts at the beginning (l=0) and the other at the end (r=n-1). They move towards each other (e.g., finding a pair with a target sum in a sorted array, reversing an array).
  • Same Direction (Fast/Slow): Pointers move in the same direction but at different speeds (e.g., finding the middle element of a linked list, detecting cycles in a list using Floyd's Tortoise and Hare method).
# Finding if a sorted array has a pair with sum == target
def has_pair_sum(arr, target):
    l, r = 0, len(arr) - 1
    while l < r:
        curr_sum = arr[l] + arr[r]
        if curr_sum == target:
            return True, (l, r)
        elif curr_sum < target:
            l += 1  # Need a larger sum
        else:
            r -= 1  # Need a smaller sum
    return False
05

Singly Linked List

A Linked List is a linear data structure where elements (nodes) are allocated dynamically in heap memory rather than contiguously. Each node contains a **Data** field and a **Next** pointer pointing to the next node in the sequence. The last node points to NULL.

Key Characteristics: No waste of memory capacity (grows dynamically), but accessing an element requires traversing from the head node, taking O(N) time.

# Singly Linked List Node representation in Python
class Node:
    def __init__(self, data):
        self.data = data
        self.next = None  # Pointer to next Node
Operation Best Case Worst Case Why?
Access / Search O(1) O(n) Must traverse sequentially from head.
Insert (Head) O(1) O(1) Simply change pointers: new_node.next = head.
Insert (End) O(1) O(n) Requires traversing to tail unless tail pointer is maintained.
Delete (Head) O(1) O(1) Just move head pointer: head = head.next.
06

Doubly Linked List

A Doubly Linked List (DLL) extends the singly linked list by adding an extra pointer field **Prev** in each node, pointing to the previous node in the list.

NULL ← [Prev | Data | Next] ↔ [Prev | Data | Next] → NULL

Advantages:

  • Can be traversed in both forward and backward directions.
  • Deletion of a node is more efficient (O(1)) if we are already given a direct reference to that node, as we can immediately link its predecessor to its successor without traversing to find the predecessor.

Disadvantages: Overhead of an extra pointer per node (prev), and pointer management during insertion/deletion is more complex.

07

Circular Linked List

In a Circular Linked List, the last node (tail) points back to the first node (head) instead of pointing to NULL. It can be singly circular or doubly circular.

Key Applications:

  • Round-Robin Scheduling: Operating Systems use circular structures to allocate CPU time slots to multiple processes sequentially in cycles.
  • Multiplayer Games: Turn-based games (like Monopoly or multiplayer board games) traverse players circularly.
  • Buffer Pools: Circular buffers for streaming media.
💡

Stack vs Queue & Dynamics

Why are Linked Lists Dynamic? Static arrays allocate a single contiguous block of memory at compile time (or fixed allocation). If elements exceed this size, it overflows. Linked lists allocate individual nodes dynamically on the **heap** during execution. Nodes are created and deleted on the fly, referencing each other via memory pointers, avoiding size bounds and massive reallocation copies.

Stack vs Queue Comparison

Criteria Stack Queue
Workflow Principle LIFO (Last In First Out) FIFO (First In First Out)
Access Ends Single end (Top) for both push and pop Two ends (Enqueue at Rear, Dequeue at Front)
Core Operations Push, Pop, Peek Enqueue, Dequeue, Front/Rear Peek
Primary Use Cases Backtracking, recursion, undo histories, matching brackets Scheduling, task queuing, asynchronous buffers
08

Stack

A Stack is a LIFO (Last In First Out) linear data structure. All operations (insertion, deletion, and lookup) occur at a single designated end called the **Top** of the stack.

Complexity: All core operations (Push, Pop, Peek) take O(1) time.

Primary Applications:

  • Recursion & Function Calls: When a function is called, its local variables and return address are pushed onto the system call stack. They are popped when the function returns.
  • Expression Evaluation: Converting and evaluating Infix expressions to Postfix/Prefix.
  • Backtracking: Storing history to go back (e.g., solving mazes, browser back button, undo operations in editors).
09

Queue

A Queue is a FIFO (First In First Out) linear data structure. Elements are inserted at the **Rear/Tail** and removed from the **Front/Head**.

Complexity: Enqueue (insert) and Dequeue (remove) take O(1) time.

Primary Applications:

  • Process Scheduling: Queueing processes ready for CPU execution.
  • Data Buffers: Asynchronous data transfers (e.g., IO buffers, keyboard buffers, print queues).
  • BFS (Breadth-First Search): Exploring graph vertices level-by-level uses a queue.
10

Deque (Double Ended Queue)

A Deque (double-ended queue) is a generalized queue that permits insertions and deletions at **both** the Front and the Rear ends.

Key Operations: insertFront(), insertLast(), deleteFront(), deleteLast().

Key Applications:

  • Sliding Window Maximum: Tracking the maximum value in all sliding windows of size K in O(N) time.
  • A-Steal Job Scheduling: Thread-pool work stealing scheduling algorithms.
11

Binary Tree

A Binary Tree is a non-linear hierarchical data structure where each node has **at most 2 children** (referred to as the Left child and the Right child).

Tree Classifications:

  • Full Binary Tree: Every node has either 0 or 2 children. No node has only 1 child.
  • Complete Binary Tree: All levels are completely filled except possibly the last level, which is filled from left to right (crucial for Binary Heaps).
  • Perfect Binary Tree: All internal nodes have exactly 2 children and all leaf nodes are at the same level.
  • Balanced Binary Tree: A tree where the height difference between the left and right subtrees of any node is at most 1 (e.g., AVL Trees, Red-Black Trees).
12

BST (Binary Search Tree)

A Binary Search Tree (BST) is a binary tree that enforces a strict ordering constraint:

Values in Left Subtree < Root Node Value < Values in Right Subtree

Time Complexity:

  • Average/Balanced Case: Searching, insertion, and deletion take O(log N) time, as the search space is halved at each step.
  • Worst Case (Skewed Tree): If elements are inserted in sorted order (e.g., 10 → 20 → 30 → 40), the tree becomes a linear chain. Searching degrades to O(N). Self-balancing BSTs (AVL, Red-Black) solve this.
13

Tree Traversals

Unlike linear structures, trees can be traversed in multiple ways depending on the visit order of the root relative to its subtrees:

Depth-First Traversals (DFS):

  • Inorder (Left, Root, Right): Traverses the left subtree, visits root, then right subtree. Crucial Property: Inorder traversal of a BST yields elements in sorted ascending order.
  • Preorder (Root, Left, Right): Visits root first, then left subtree, then right subtree. Used to create copies of trees or prefix expression representations.
  • Postorder (Left, Right, Root): Traverses subtrees first, then visits the root. Used to delete nodes (bottom-up deletion) or evaluate postfix expressions.

Breadth-First Traversal (BFS / Level Order): Visits nodes level by level, starting from the root (uses a Queue buffer).

# Recursive DFS Inorder Traversal in Python
def inorder(root):
    if root:
        inorder(root.left)
        print(root.data, end=" ")
        inorder(root.right)
14

Heap

A Heap is a specialized **Complete Binary Tree** stored in an array representation instead of pointer nodes. Since it's complete, it can be mapped into indices:

Left Child of Node at index i = 2i + 1
Right Child of Node at index i = 2i + 2
Parent of Node at index i = (i - 1) // 2

Heap Properties:

  • Max Heap: The value of the parent node is always greater than or equal to the values of its children. The root holds the maximum element.
  • Min Heap: The value of the parent node is always less than or equal to the values of its children. The root holds the minimum element.

Key Complexities:

  • Heapify: Restoring the heap property after insertion or deletion takes O(log N).
  • Build Heap: Creating a heap from a raw array of N elements takes O(N) using Floyd's algorithm.
15

Priority Queue

A Priority Queue is an abstract data structure where each element has a "priority" associated with it. Elements with higher priorities are dequeued before lower priority ones. It is highly optimized when implemented using a **Heap**.

Heap vs BST Comparison

Operation / Feature Binary Heap (Min/Max Heap) Binary Search Tree (BST)
Search Time O(n) (No ordering between siblings) O(log n) average (Ordered left < root < right)
Find Min or Max O(1) (Located at the root) O(log n) (Must traverse to leftmost or rightmost leaf)
Build Time O(n) O(n log n)
Array Representation Yes, very natural since it is complete. No, sparse pointer nodes are needed.

DSA Technical Viva Q&A

Q1: Explain locality of reference in Arrays vs Linked Lists.

Answer: Arrays have high spatial locality of reference because their elements are stored in contiguous memory blocks. When a CPU accesses an array index, cache line prefetching loads adjacent elements into cache memory, leading to fast subsequent access times (cache hits). Linked lists, however, contain nodes scattered randomly across the heap. Accessing next nodes requires dereferencing pointers, leading to frequent cache misses and slower traversal in hardware.

Q2: What is call stack overflow in recursion?

Answer: Every recursive function call allocates a stack frame on the thread's call stack to store local variables, parameters, and return memory. If a recursive function fails to reach its base case, or if the recursion is too deep, stack frames are added continuously without popping. Eventually, the call stack exceeds its allocated size, resulting in a **Stack Overflow** crash.

Q3: Why are self-balancing trees (AVL, Red-Black) preferred over standard BSTs in production?

Answer: Standard BSTs have an average search time of O(log N), but if values are inserted in sorted order, the tree becomes skewed, resembling a linked list with O(N) search time. Self-balancing trees automatically perform adjustments (rotations) on insertions and deletions to keep the height bounded to O(log N), guaranteeing logarithmic bounds for all search, insert, and delete operations.

Q4: What is amortized time complexity? Explain with Dynamic Array resizing.

Answer: Amortized complexity is the average time taken per operation over a worst-case sequence of operations. For instance, when inserting into a dynamic array (like Python's list), most insertions take O(1) time because there is empty capacity. However, when the array becomes full, it reallocates memory and copies all N elements, taking O(N) once. Since this reallocation occurs only after doubling the size (at 1, 2, 4, 8... steps), the total cost of N insertions is O(N). Averaged out, each insertion takes O(N) / N = O(1) amortized time.

Q5: Explain Floyd's Cycle-Finding Algorithm (Tortoise and Hare) for Linked Lists.

Answer: To detect a cycle in a linked list, we initialize two pointers at the head: a slow pointer (Tortoise) that moves 1 step at a time, and a fast pointer (Hare) that moves 2 steps. If there is no cycle, the fast pointer reaches the end (NULL). If a cycle exists, the fast pointer enters the loop first. Because it moves 1 node closer to the slow pointer in each iteration, the fast pointer is guaranteed to eventually catch up and meet the slow pointer inside the loop. This detects cycles in O(N) time with O(1) auxiliary space.

Q6: How does Stack memory differ from Heap memory allocation?

Answer: Stack memory is allocated for execution threads to store local function variables and call frames. It is automatically managed (LIFO order), very fast to allocate, and limited in size. Heap memory is allocated dynamically during runtime for objects, collections, and linked structures. It is managed manually (or via garbage collection), slower to access/allocate due to pointer lookups, and much larger in size.

Time Complexity

Time complexity quantifies the rate at which the execution time of an algorithm grows as the input size N increases. It does not measure the actual runtime in seconds (which depends on hardware), but rather the count of primitive operations performed.

Asymptotic Analysis: We study performance as input size approaches infinity (N → ∞), focusing on the highest-order term and ignoring constant multipliers. For example, if an algorithm does 3N² + 5N + 12 operations, its asymptotic time complexity is O(N²).

17

Space Complexity

Space complexity measures the total memory space consumed by an algorithm relative to the input size N. It is divided into:

  • Input Space: The memory required to store the input data itself.
  • Auxiliary Space: The temporary/extra space allocated by the algorithm during execution (e.g., intermediate arrays, recursion call stack frames). Placement interviewers are usually asking for **Auxiliary Space**.
18

Big O Notation & Growth Rates

Big O describes the **worst-case** upper bound of growth. It guarantees that the execution time will not exceed this limit for sufficiently large inputs.

Common Complexity Classes

Class Name Typical Code Pattern
O(1) Constant Math formulas, array indexing, simple operations.
O(log N) Logarithmic Binary search (input size divides by 2 in each loop).
O(N) Linear Single loop traversing elements 0 to N.
O(N log N) Linearithmic Divide-and-conquer sorting (Merge Sort, Quick Sort).
O(N²) Quadratic Nested loops (Bubble Sort, checking all pairs).
O(2^N) Exponential Naïve recursive Fibonacci, generating subsets.

Comparing Growth Rates

Consider input size N = 1000 (performing 10^8 operations per second):

  • O(log N): ≈ 10 operations (takes nanoseconds).
  • O(N): 1000 operations (takes microseconds).
  • O(N log N): ≈ 10,000 operations (takes microseconds).
  • O(N²): 1,000,000 operations (takes milliseconds).
  • O(2^N): 2^1000 operations (would take trillions of years to complete!).
🔑

Why Hashing Improves Complexity

Without Hashing, searching for an element in an unsorted array takes O(N) linear scan. Even if the array is sorted, searching takes O(log N) via Binary Search.

Hashing: By mapping keys to indices via a Hash Function, we can insert, delete, and lookup values in O(1) average time.

Interview Applications: Hashing is the ultimate tool for optimizing search complexity in coding rounds. Common patterns include:

  • Two Sum (O(N) instead of O(N²)): Store seen elements in a hash map: seen[num] = index. As we traverse, check if target - num is already in the map.
  • Duplicate Detection: Store elements in a Hash Set. If an element is already present, a duplicate is found in O(1) lookup.
  • Frequency Counters (Anagrams): Map characters to their frequency counts. Compare maps in linear time.
19

BFS (Breadth First Search)

BFS is an algorithm for traversing or searching tree or graph data structures. It starts at a source node and explores all neighbor nodes at the present depth level before moving to the nodes at the next depth level.

Data Structure: Uses a Queue to track nodes to visit, and a Visited array/set to prevent re-entering cycles.

Complexity: O(V + E) where V is vertices and E is edges.

Placement Applications:

  • Finding the shortest path in an unweighted graph (first time a node is reached, it is via the shortest path).
  • Social Network analysis (finding connections at degree 1, degree 2).
20

DFS (Depth First Search)

DFS explores a graph by going as deep as possible along each branch before backtracking. It continues until all reachable nodes have been visited.

Data Structure: Uses a **Stack** (either explicitly or implicitly via **Recursion**), and a **Visited** array/set.

Complexity: O(V + E) where V is vertices and E is edges.

Placement Applications:

  • Detecting cycles in directed/undirected graphs.
  • Topological Sorting (ordering tasks with dependencies).
  • Solving puzzle paths (like mazes or Sudoku).

BFS vs DFS Comparison

Feature BFS DFS
Underlying Structure Queue Stack / Recursion
Traversal Strategy Level-by-level (wide) Branch-by-branch (deep)
Memory Demand O(Width of Graph) - high for wide trees. O(Height of Graph) - low for balanced trees.
Shortest Path Guaranteed for unweighted graphs. Not guaranteed (visits path-by-path).
21

Dijkstra's Algorithm

Dijkstra's algorithm finds the shortest path from a single source node to all other nodes in a weighted graph. It works greedily: in each step, it selects the unvisited node with the smallest tentative distance and relaxes its outgoing edges.

Constraint: Edge weights **must be non-negative** (Weights ≥ 0).

Complexity: O((V + E) log V) when optimized with a Min-Heap / Priority Queue.

Why Dijkstra Fails on Negative Edges

Dijkstra works on the greedy assumption that once a node's shortest path is finalized, it cannot be improved further. If there are negative edges, a longer path with a negative weight could eventually lead to a smaller total distance, but Dijkstra will have already locked the node, skipping this path.

Alternative: Use the **Bellman-Ford Algorithm** (O(V · E)), which can handle negative weights and detect negative cycles.

22

Sorting Algorithms

Sorting arranges elements in a specific order (ascending/descending). Standard placement sorting algorithms include:

  • Bubble Sort (O(N²)): Repeatedly swap adjacent elements if they are in the wrong order. Very slow.
  • Selection Sort (O(N²)): Repeatedly find the minimum element from the unsorted part and put it at the beginning. Unstable.
  • Insertion Sort (O(N²)): Build the sorted array one item at a time by shifting elements. Best case is O(N) when already sorted (extremely efficient for small/nearly sorted arrays).
  • Merge Sort (O(N log N)): Divide array in half, recursively sort both halves, then merge them. Guaranteed O(N log N) but requires O(N) auxiliary space for merging. Stable.
  • Quick Sort (Avg O(N log N), Worst O(N²)): Choose a pivot, partition the array so left side < pivot < right side, and recursively sort. Average case is extremely fast due to low constant factors. In-place but unstable.

Merge Sort vs Quick Sort

Criteria Merge Sort Quick Sort
Time Complexity Guaranteed O(N log N) in all cases. O(N log N) average, O(N²) worst case.
Space Complexity O(N) auxiliary space (not in-place). O(log N) stack space (in-place).
Stability Stable (preserves relative order). Unstable.
Cache Performance Average cache performance. Excellent cache performance (faster in practice).
23

Greedy Method

The Greedy paradigm builds a solution piece-by-piece, making the **locally optimal choice** at each step with the hope that this will lead to the globally optimal solution.

Characteristics: Fast and simple to implement, but does not always yield correct results because it does not reconsider past choices.

Successful Examples: Fractional Knapsack, Activity Selection (Interval Scheduling), Dijkstra's Algorithm, Kruskal's/Prim's MST, Huffman Coding.

Greedy Fail Case: Coin Change Problem. If coins are {1, 3, 4} and target is 6, greedy chooses {4, 1, 1} (3 coins), but optimal is {3, 3} (2 coins).

24

Dynamic Programming (DP)

Dynamic Programming solves complex problems by breaking them into smaller subproblems. It is used when the problem exhibits two properties:

  • Overlapping Subproblems: The same subproblems are solved repeatedly (e.g., computing fib(3) multiple times). We solve once and store the result.
  • Optimal Substructure: The global optimal solution can be constructed from optimal solutions of its subproblems.

Implementation Approaches:

  • Memoization (Top-Down): Recursive strategy where we check if a state is computed before executing. Stores results in a hash table or array.
  • Tabulation (Bottom-Up): Iterative strategy where we solve base cases first and fill a table (DP array) sequentially.

Greedy vs Dynamic Programming

Feature Greedy Paradigm Dynamic Programming (DP)
Choice Evaluation Makes local choice without evaluating subproblems. Evaluates all subproblems to make global choice.
Complexity Faster and uses less memory. Slower and requires a DP state table.
Correctness Not guaranteed to be optimal for all problems. Guaranteed to find optimal solution if DP properties hold.

AAD Technical Viva Q&A

Q1: Stable vs Unstable sorting algorithms - why does it matter?

Answer: A sorting algorithm is **stable** if it preserves the relative order of duplicate elements. For example, if we sort a list of student records by age, and two students are 20 years old, a stable sort keeps them in their original order. Stability is critical when sorting objects by multiple criteria sequentially (e.g., sorting by name first, then sorting by age).

Stable sorts: Merge Sort, Insertion Sort, Bubble Sort.
Unstable sorts: Quick Sort, Heap Sort, Selection Sort.

Q2: Adjacency Matrix vs Adjacency List for Graphs - when to use which?

Answer: An **Adjacency Matrix** is a V × V boolean grid. It takes O(V²) space but allows checking if edge (u,v) exists in O(1) time. An **Adjacency List** uses an array of linked lists/vectors, taking O(V + E) space, but checking edge existence requires searching the list (O(Degree(u))). Use Matrix for **dense graphs** (E ≈ V²) and List for **sparse graphs** (E ≪ V², which is most real-world scenarios).

Q3: Explain the difference between Divide & Conquer and Dynamic Programming.

Answer: In **Divide & Conquer**, the subproblems are independent of each other. We solve them independently and combine them (e.g., in Merge Sort, sorting the left half has nothing to do with sorting the right half). In **Dynamic Programming**, the subproblems are overlapping. The same subproblems are needed multiple times, so DP caches results to avoid recomputation.

Q4: What is Auxiliary Space and how does it differ from Space Complexity?

Answer: **Space Complexity** is the total space taken by the program including the inputs. **Auxiliary Space** is the temporary extra space allocated by the algorithm during execution (variables, temporary tables, stacks). For example, finding the maximum element in an array of size N takes O(N) space complexity (to store the array), but only O(1) auxiliary space (a single variable for the max value).

Q5: What are collision resolution techniques in Hashing?

Answer: When different keys hash to the same index, a collision occurs. Resolution methods include:

  • Chaining (Open Hashing): Each bucket of the hash table contains a linked list of elements. Collided items are appended to the list at that index.
  • Open Addressing (Closed Hashing): All elements are stored in the hash table itself. If a collision occurs, we probe other cells using methods like Linear Probing (check index +1, +2...), Quadratic Probing, or Double Hashing.

Q6: Why does Dijkstra's algorithm fail for negative edge weights? Give a numerical example.

Answer: Dijkstra locks a node's distance once it is visited. Consider a graph with nodes A, B, and C. Directed edges: A → B (weight 5), A → C (weight 2), and B → C (weight -10). Starting at A: Tentative distances are B=5, C=2. Dijkstra picks C (smallest, distance 2) and locks C. Next, it visits B (distance 5). The path A → B → C has total weight 5 + (-10) = -5, which is better than 2. But since C was already visited and locked, Dijkstra fails to update C, yielding an incorrect shortest path.

01

Percentage

Core Conversions
x% = x / 100
e.g. 20% = 20/100 = 1/5
a/b as % = (a/b) × 100
e.g. 1/4 = 25%
Percentage Change in Consumption
Price increases by R% → reduce consumption by:
[R / (100 + R)] × 100 %
(to keep expenditure unchanged)
Price decreases by R% → increase consumption by:
[R / (100 − R)] × 100 %
(to keep expenditure unchanged)
Population Growth
Population after n years = P × (1 + R/100)ⁿ
Population n years ago = P / (1 + R/100)ⁿ
Depreciation
Value after n years = P × (1 − R/100)ⁿ
Value n years ago = P / (1 − R/100)ⁿ
Comparative Percentage
A is R% more than B → B is less than A by:
[R / (100 + R)] × 100 %
A is R% less than B → B is more than A by:
[R / (100 − R)] × 100 %
02

Profit & Loss

Basic Relations
  • Gain = SP − CP  (when SP > CP)
  • Loss = CP − SP  (when SP < CP)
  • Gain / Loss is always calculated on CP
Percentage Formulas
Gain % = (Gain / CP) × 100
Loss % = (Loss / CP) × 100
Selling Price
SP = [(100 + Gain%) / 100] × CP
e.g. sold at 35% gain → SP = 135% of CP
SP = [(100 − Loss%) / 100] × CP
e.g. sold at 35% loss → SP = 65% of CP
Cost Price
CP = [100 / (100 + Gain%)] × SP
CP = [100 / (100 − Loss%)] × SP
Special Cases
Two items sold each at ±x% (one gain, one loss):
Net Loss % = (x/10)² %
Always a loss when same % used for gain & loss
False weight trick:
Gain % = [Error / (True value − Error)] × 100
03

Time & Work

Core Principle
A finishes work in n days → A's 1 day work = 1/n
A's 1 day work = 1/n → A finishes in n days
Combined Work
A (n days) + B (m days) together:
Together finish in = nm/(n+m) days
Efficiency Ratio
A is k times as efficient as B:
Work ratio A:B = k:1
Time ratio A:B = 1:k
04

Ratio & Proportion

Basics
  • Ratio a:b = a/b  (a = antecedent, b = consequent)
  • Multiplying/dividing both terms by same nonzero number does not change the ratio
Proportion
  • a:b = c:d → a:b::c:d (a, d = extremes; b, c = means)
  • Product of means = Product of extremes: b×c = a×d
  • Fourth proportional to a,b,c → d = bc/a
  • Third proportional to a,b → c = b²/a
  • Mean proportional between a and b → √(ab)
Derived Ratios
Compounded ratio of (a:b), (c:d), (e:f) = ace : bdf
Duplicate ratio of a:b = a² : b²
Sub-duplicate = √a : √b
Triplicate = a³ : b³
Sub-triplicate = a^(1/3) : b^(1/3)
Componendo & Dividendo:
If a/b = c/d → (a+b)/(a−b) = (c+d)/(c−d)
Variation
Direct: x ∝ y → x = ky
Inverse: x ∝ 1/y → xy = k
05

Average

Core Formula
Average = Sum of observations / Number of observations
Average Speed
Equal distances at speeds x and y kmph:
Average speed = 2xy / (x + y) kmph
This is the Harmonic Mean of x and y
06

Numbers / HCF & LCM

Algebraic Identities
  • (a+b)(a−b) = a² − b²
  • (a+b)² = a² + 2ab + b²
  • (a−b)² = a² − 2ab + b²
  • (a+b+c)² = a²+b²+c²+2(ab+bc+ca)
  • a³+b³ = (a+b)(a²−ab+b²)
  • a³−b³ = (a−b)(a²+ab+b²)
  • a³+b³+c³−3abc = (a+b+c)(a²+b²+c²−ab−bc−ca)
  • If a+b+c = 0 → a³+b³+c³ = 3abc
HCF & LCM Key Rules
HCF × LCM = Product of two numbers
Valid for exactly two numbers
HCF of fractions = HCF of numerators / LCM of denominators
LCM of fractions = LCM of numerators / HCF of denominators
BODMAS Order
Brackets → Of → Division → Multiplication → Addition → Subtraction
Bracket order: ( ) → { } → | |
Modulus
|a| = a if a > 0 ; −a if a < 0
e.g. |−5| = 5, |5| = 5
07

Permutation & Combination

Factorial
n! = n × (n−1) × (n−2) × … × 2 × 1
0! = 1  |  4! = 24  |  5! = 120
Permutations (Ordered)
ⁿPᵣ = n! / (n−r)!
= n(n−1)(n−2)…(n−r+1)
e.g. ⁶P₂ = 6×5 = 30
All n taken at a time: ⁿPₙ = n!
Repeated elements (p₁ alike, p₂ alike …):
Arrangements = n! / (p₁! × p₂! × … × pᵣ!)
where p₁+p₂+…+pᵣ = n
Combinations (Unordered)
ⁿCᵣ = n! / [r! × (n−r)!]
e.g. ¹¹C₄ = (11×10×9×8)/(4×3×2×1) = 330
ⁿC₀ = ⁿCₙ = 1
ⁿCᵣ = ⁿC₍ₙ₋ᵣ₎
e.g. ¹⁶C₁₃ = ¹⁶C₃ = 560
08

Probability

Core Formula
P(E) = n(E) / n(S)
n(E) = favourable outcomes, n(S) = total outcomes
Key Results
  • P(S) = 1  (certain event)
  • 0 ≤ P(E) ≤ 1
  • P(∅) = 0  (impossible event)
  • P(A∪B) = P(A) + P(B) − P(A∩B)
  • P(A') = 1 − P(A)  (complement)
Standard Sample Spaces
  • 1 coin toss: S = {H, T}  → n(S) = 2
  • 2 coins: S = {HH, HT, TH, TT}  → n(S) = 4
  • 1 die: S = {1,2,3,4,5,6}  → n(S) = 6
  • Deck of cards: n(S) = 52  (13 per suit × 4 suits)
  • Face cards per suit: King, Queen, Jack → 3; total = 12
  • Red cards = Hearts + Diamonds = 26; Black = Spades + Clubs = 26

Simple & Compound Interest

Simple Interest
SI = (P × R × T) / 100
P = (100 × SI) / (R × T)
R = (100 × SI) / (P × T)
T = (100 × SI) / (P × R)
P = Principal, R = Rate % p.a., T = Time in years
Compound Interest — Amount Formulas
Compounded Annually:
A = P × (1 + R/100)ⁿ
Compounded Half-yearly:
A = P × (1 + R/200)²ⁿ
Rate halved, periods doubled
Compounded Quarterly:
A = P × (1 + R/400)⁴ⁿ
Rate quartered, periods quadrupled
Annually, time = 3½ years:
A = P × (1 + R/100)³ × (1 + R/200)
Whole years use full rate; fraction year uses proportional rate simply
Different rates R₁, R₂, R₃ for years 1, 2, 3:
A = P × (1+R₁/100)(1+R₂/100)(1+R₃/100)
CI & Present Worth
CI = A − P
Present Worth of amount x due n years hence:
PW = x / (1 + R/100)ⁿ

Speed, Time & Distance

Core Relations
Speed = Distance / Time
Time = Distance / Speed
Distance = Speed × Time
Unit Conversion
km/hr → m/s : × 5/18
m/s → km/hr : × 18/5
Speed Ratio & Time Ratio
Speed ratio A:B = a:b
→ Time ratio A:B = b:a
(Same distance; time inversely proportional to speed)
Average Speed
Equal distances at x and y km/hr:
Avg speed = 2xy / (x + y) km/hr
Harmonic mean of the two speeds

Problems on Trains

Conversion (same as speed)
km/hr → m/s : × 5/18  |  m/s → km/hr : × 18/5
Time to Cross
  • Train (length l) crosses a pole / standing person → covers l metres
  • Train (length l) crosses stationary object (length b) → covers (l + b) metres
Relative Speed
Same direction (u > v): Relative speed = u − v
Opposite directions: Relative speed = u + v
Crossing Each Other
Trains of length a & b, opposite directions:
Time = (a + b) / (u + v) sec
Same direction:
Time = (a + b) / (u − v) sec
Speed Ratio (Meeting Problem)
Two trains start from A & B, after crossing take a sec and b sec to reach opposite ends:
Speed A : Speed B = √b : √a
Note: ratio is √b : √a, not b : a

Boats & Streams

Definitions
  • Downstream: along the stream (boat + current)
  • Upstream: against the stream (boat − current)
Speed Formulas
Boat speed in still water = u, stream = v:
Downstream speed = u + v
Upstream speed = u − v
Given downstream = a, upstream = b:
Speed in still water = (a + b) / 2
Rate of stream = (a − b) / 2

Pipes & Cisterns

Basic Rates
Inlet fills in x hrs → fills 1/x per hour
Outlet empties in y hrs → empties 1/y per hour
Combined Pipes
Inlet (x hrs) + Outlet (y hrs), y > x:
Net fill per hour = 1/x − 1/y
Tank fills in xy/(y−x) hrs
Inlet (x hrs) + Outlet (y hrs), x > y:
Net empty per hour = 1/y − 1/x
Tank empties in xy/(x−y) hrs

Stocks & Shares

Key Definitions
  • Face Value (FV): printed value on share certificate — always fixed
  • Market Value (MV): current traded price — changes daily
  • Dividend: annual profit paid on face value
  • At premium: MV > FV  |  At par: MV = FV  |  At discount: MV < FV
  • Brokerage: added when buying; subtracted when selling
Market Value Examples
Rs.100 stock at premium of 16 → MV = Rs.116
Rs.100 stock at discount of 7 → MV = Rs.93
Number of Shares & Yield
No. of shares = Total Investment / MV per share
               = Total Income / Dividend per share
Rate of return % =
(Annual dividend / MV) × 100
e.g. 9% stock at 120 → return = (9/120)×100 = 7.5%

Banker's & True Discount

True Discount Concepts
  • Present Worth (PW): amount paid now to clear a future debt
  • True Discount (TD) = Sum due − PW = SI on PW
  • Amount = PW + TD
True Discount Formulas
PW = (100 × Amount) / (100 + R×T)
TD = (Amount × R × T) / (100 + R×T)
TD = (PW × R × T) / 100
Sum due (when SI and TD known):
Sum = (SI × TD) / (SI − TD)
PW with compound interest:
PW = Amount / (1 + R/100)ᵀ
Banker's Discount Formulas
BD = SI on Face Value for unexpired time
BD = (Amount × R × T) / 100
BG = BD − TD = SI on TD = TD² / PW
TD = √(PW × BG)
Amount = (BD × TD) / (BD − TD)
TD = (BG × 100) / (R × T)

Logarithms, Surds & Indices

Logarithm Definition
aᵐ = x  ⟺  m = logₐ x
e.g. 10³ = 1000 ↔ log₁₀ 1000 = 3
e.g. 3⁴ = 81 ↔ log₃ 81 = 4
Log Properties
logₐ(xy) = logₐx + logₐy
logₐ(x/y) = logₐx − logₐy
logₐ(xⁿ) = n·logₐx
logₓ x = 1
logₐ 1 = 0
logₐ x = 1 / logₓ a
logₐ x = log x / log a (change of base)
Laws of Indices
aᵐ × aⁿ = aᵐ⁺ⁿ
aᵐ / aⁿ = aᵐ⁻ⁿ
(aᵐ)ⁿ = aᵐⁿ
(ab)ⁿ = aⁿbⁿ
(a/b)ⁿ = aⁿ/bⁿ
a⁰ = 1
Laws of Surds
ⁿ√a = a^(1/n)
√(ab) = √a × √b
√(a/b) = √a / √b
(√a)ⁿ = a^(n/2)

Chain Rule

Direct & Indirect Relations
  • Direct Proportion: if one quantity increases, the other increases proportionally. Set up as a direct ratio. (e.g. more articles → more cost)
  • Indirect Proportion: if one increases, the other decreases. Invert the ratio. (e.g. more speed → less time)
  • For multi-variable problems, compare each item with the unknown and multiply all ratios together.

Calendar

Leap Year Rules
  • Divisible by 4 but not a century → Leap year
  • Century year divisible by 400 → Leap year (e.g. 400, 800, 1200, 1600, 2000)
  • Century year NOT divisible by 400 → NOT a leap year (e.g. 100, 200, 300, 1800, 2100)
  • Leap year = 366 days; Ordinary year = 365 days
Odd Days
1 ordinary year = 52 weeks + 1 odd day
1 leap year = 52 weeks + 2 odd days
100 years → 5 odd days
200 years → 3 odd days
300 years → 1 odd day
400 years → 0 odd days
800, 1200, 1600, 2000 … → 0 odd days each
Odd Days → Day of Week
0 = Sun | 1 = Mon | 2 = Tue | 3 = Wed | 4 = Thu | 5 = Fri | 6 = Sat

Clocks

Speed of Hands
Minute hand: 360° in 60 min = 6°/min
Hour hand: 360° in 12 hrs = 0.5°/min
Relative speed: 5.5°/min
Minute hand gains 5.5° over hour hand per minute
Key Results
  • In 60 minutes, minute hand gains 55 minute-spaces on hour hand
  • Both hands coincide once every hour
  • Hands at right angles (90°): 15 minute-spaces apart — happens twice per hour
  • Hands opposite (180°): 30 minute-spaces apart — happens once per hour
  • Clock fast: shows time ahead; Clock slow: shows time behind
Angle Formula
Angle between hands at H hrs M mins:
θ = |30H − 5.5M|°
If θ > 180°, subtract from 360°

Races & Games

Terminology
  • Start of x metres: A runs 100m while B runs (100−x) m
  • Beats B by x m: same as giving B a start of x m
  • Dead heat: all contestants reach goal simultaneously
  • Game of 100: first to score 100 points wins
  • "A can give B 20 points in 100" → A scores 100 while B scores 80

Volume & Surface Area

Cuboid (l × b × h) & Cube (edge a)
Cuboid Volume = l × b × h  |  SA = 2(lb + bh + lh)  |  Diagonal = √(l² + b² + h²)
Cube Volume = a³  |  SA = 6a²  |  Diagonal = a√3
Cylinder (r, h) & Cone (r, h)
Cylinder Volume = πr²h  |  Curved SA = 2πrh  |  Total SA = 2πr(h + r)
Cone Slant height l = √(h² + r²)  |  Volume = (1/3)πr²h  |  Curved SA = πrl  |  Total SA = πr(l + r)
Sphere (r) & Hemisphere (r)
Sphere Volume = (4/3)πr³  |  SA = 4πr²
Hemisphere Volume = (2/3)πr³  |  Curved SA = 2πr²  |  Total SA = 3πr²
1 litre = 1000 cm³

Trigonometry & Heights & Distances

Ratios (right-angled △, angle θ)
sin θ = Opp / Hyp  |  cos θ = Adj / Hyp  |  tan θ = Opp / Adj
cosec θ = 1 / sin θ  |  sec θ = 1 / cos θ  |  cot θ = 1 / tan θ
Identities & Values
sin²θ + cos²θ = 1  |  1 + tan²θ = sec²θ  |  1 + cot²θ = cosec²θ
sin 30° = 1/2  |  sin 45° = 1/√2  |  sin 60° = √3/2  |  sin 90° = 1
cos 30° = √3/2  |  cos 45° = 1/√2  |  cos 60° = 1/2  |  cos 90° = 0
tan 30° = 1/√3  |  tan 45° = 1  |  tan 60° = √3  |  tan 90° = ∞
Heights & Distances
  • Angle of Elevation: angle between horizontal and line of sight looking up at an object
  • Angle of Depression: angle between horizontal and line of sight looking down at an object
  • tan(θ) = Height / Horizontal distance — most common relation used
